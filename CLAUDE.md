# SYRUP – project knowledge for Claude

Home Assistant custom integration (HACS) that reads a **SYR Safe-T+ Connect** leak protection unit without the vendor cloud. The device has no local API (port 5333 closed, port 80 answers every path with an empty 200), so SYRUP impersonates the cloud endpoint the device already talks to and optionally relays to the real cloud.

Author: ottelo – github.com/ottelo9 (remote `https://github.com/ottelo9/syrup.git`, branch `master`).

## RS-485 service bus (TinyC program)

- RJ10 (4P4C) under the device, RS-485 on the two middle pins, 19200 8N1, plain ASCII. Outer pins undocumented.
- The WLAN control box is bus master and polls every ~10 s while it is online with the cloud: request `CR LF ESC "1:" getBAR CR LF`, response `2529 mbar CR` (values only, no names). The `1:` is the same prefix as in the cloud XML – the box forwards cloud commands onto the bus. Documented writes: `setAB1` open, `setAB2` close.
- `syr_rs485.tc` only receives (`serialBegin(rx, -1, …)`, transceiver DE on GND). Requests go into a 16-entry FIFO, each response line pops one; per-param plausibility checks, resync after 1 s silence.
- Console: `SyrPin <gpio>` (persist, stored as GPIO+1 so 0 = unset), `SyrRaw 0|1|2`. JSON: `,"SYR":{"Alter","Druck","Entnahme","Volumen","Ventil","Alarm","Spannung"}` – German keys avoid Tasmota's HA auto device classes.
- Build: gemu's compiler via Node (`tcc.mjs`, see the tasmota-sml-script notes). Test: gemu's JS VM with syscall 555 (`serialReadArray`) overridden to feed simulated bus traffic.

## Protocol (verified against captures)

- Device → `POST http://iot1.syrconnect.de/WebServices/SyrConnectDeviceWebService.asmx/GetAllCommands` every 10 s, plain HTTP, no auth, `User-Agent: Husty Control-Box` (firmware by Husty, Poland, not SYR). Body: `xml=<sc><cp v="XXXX"/><dat v="PAYLOAD"/></sc>`.
- Payload = plaintext XML **XOR one-byte key** (changes per message; seen 0x14–0x1E), then 7 bytes replaced: `" % & ' + < >` (0x22 0x25 0x26 0x27 0x2B 0x3C 0x3E) → `Ä ä Ü ö € Ö ü`, then UTF-8.
- **0x7F rule:** if a char XORs to 0x7F (DEL), the unchanged char is sent. Decode: `v = c ^ key; char = c if v == 0x7F else v`. (Earlier this was misread as "firmware drops bytes" – wrong.)
- Key is not taken from `cp`; recover it from the known prefix `<d>` (device) / `<sc>` (cloud): `key = cipher[1] ^ ord('d')`. `cipher[0]` is always escaped.
- Device payload: `<d><c n="1:getSRN" v="..."/>…</d><ci m="MAC" f="fw" b="3"/><cs v="…"/>` – several root elements, so parse with regex, not an XML parser.
- Cloud response: `<sc><d>` + empty `get…` fields (= poll request) + `</d><ct rt="10"/></sc>`. Commands are presumably `set…` fields with a value (e.g. `setAB`) – **not verified on the device**.
- Known values: `SRN` serial, `VER` type, `AB` valve (1 = open), `ALA` alarm (`FF` = none), `ALM` history, `AVO` current withdrawal (mL), `BAR` pressure (`2529 mbar`), `VOL` total (`Vol[L]951727`), `NET` supply (`ADC:933 6,05V`), `SRV` service date. Unclear: `NPS TPA VLV T1 T2 TBS TC TO TMP TYP UL REL 71`, `cp`, `cs`.

## Integration behaviour

- `SyrupDeviceView` registers the exact device path (`requires_auth = False`, once per HA run via `VIEW_REGISTERED`).
- Default `relay_url` = real cloud: forward body, return cloud response unchanged (app keeps working). SYRUP answers itself only when a command is pending (`hub.pending`), reusing the device's key.
- Port 80 → HA 8123 bridge and DNS override for `iot1.syrconnect.de` are the user's job (documented in README).

## Testing / CI

- `pytest` from repo root; `tests/conftest.py` puts `custom_components/syrup` on `sys.path` (codec/protocol import without HA). 19 tests.
- Fixtures have capture gaps at TCP segment boundaries (e.g. `BAR` in the key 0x1E messages) – assert only on values stable across all four.
- CI green. hacs/action needs GitHub **topics** (repo metadata, set in the About dialog) and `brand/icon.png`.
- Node 20 deprecation warning for `actions/checkout@v4` – harmless.

## Conventions

- User-facing docs (README, `docs/`, docstrings, `de.json`) German **with umlauts**; these memory files English.
- Python identifiers stay ASCII (e.g. `test_schluessel_…`).
- `.ps1` files stay ASCII: Windows PowerShell 5.1 reads BOM-less scripts as ANSI.
- `.gitattributes`: `*.bin binary` – fixtures must never get EOL conversion.
- Versions are release dates, `YYYY.MM.DD` (second release that day: `.1`). Dashes (`2026-09-30`) are rejected by HA/AwesomeVersion and block loading. `manifest.json` `version` and the GitHub release tag must be identical; bump the manifest first, then create the release. No pre-releases – HACS hides them.
